# 기획 한 장 — 영어·스페인어·한국어 한 줄 사전 (v2.1 · 픽셀 테마)

> **v1 → v2 변경 요약**: 번역 엔진을 MyMemory에서 NVIDIA NIM(LLM)으로 교체하고, 사전 교차검증·문장 요소 대응·단어장·배틀 연출을 추가했다.
> v1에 있던 "고정 파일(fixtures) 모드"는 폐기했다(8장 참고). 이 문서의 수치는 2026-10-07 직접 측정한 값이다.
>
> **v2 → v2.1 변경 요약**: 화면을 **픽셀 아트 RPG 테마**로 개편했다(6-1장). 정보 구조(EN|ES|KO 3카드, 우측 사이드)는 그대로이고, 겉모습·배틀 화면·마스코트·도감 레벨이 바뀌었다.

## 1. 문제 문장
영어·스페인어를 한국어로 병행 학습할 때, 모르는 단어·문장의 뜻을 언어별로 따로 찾고 정리하느라
흐름이 끊긴다. 게다가 번역 결과가 맞는지 확인할 방법이 없어, 틀린 뜻을 그대로 외울 위험이 있다.

## 2. 5 Whys
1. 왜 흐름이 끊기나? → 모르는 표현마다 사전/번역 앱을 번갈아 켜야 해서
2. 왜 번갈아 켜야 하나? → 번역 도구가 대개 "출발어 1개 → 도착어 1개" 한 쌍만 보여줘서, 세 언어를 맞춰 보려면 여러 번 조회해야 해서
3. 왜 맞춰 보는 게 중요한가? → 언어마다 어순·조사·생략이 달라서(예: 한국어는 동사가 끝, 스페인어는 주어 생략) 통문장 번역만으로는 "어느 단어가 어느 단어에 대응하는지"가 안 보여서
4. 왜 번역을 믿기 어렵나? → 기계번역은 틀려도 자신 있게 출력하고, 도구가 내놓는 점수(신뢰도)가 정확성과 무관한 경우가 있어서(실측: 5장)
5. 왜 지금까지 참고 썼나? → 매번 "이번 한 번만"이라 생각해 누적 시간 손실과 오학습 위험을 체감하지 못해서

## 3. 진짜 원인 (한 줄)
세 언어를 **한 번에 대응시켜** 보여주고 **번역의 정확성을 검증할 단서**까지 주는 도구가 없어서,
매번 수동으로 여러 번 찾고, 맞는지도 스스로 판단해야 했다.

## 4. 해결 방법 비교

| 방법 | 설명 | 한계 |
|---|---|---|
| A. 그대로 유지 | 번역 앱·사전 사이트 번갈아 사용 | 추가 작업 없음 / 비효율 그대로 |
| B. 일반 번역 앱(Google 번역, Papago 등) | 이미 익숙하고 정확도도 높음 | 도착어를 하나씩 고르는 구조라 세 언어를 한 화면에서 대응시켜 보기 어렵고, 단어 대응·사전 검증 기능이 없음 |
| C. 사전 사이트(Wiktionary, WordReference) | 정의·품사·예문이 풍부 | 언어쌍 단위로 따로 찾아야 하고 문장 번역은 안 됨 |
| D. 유료 사전 구독 | 품질 높음 | 비용 발생, 조건(무료·로컬) 불일치 |
| **E. 직접 제작 (채택)** | LLM 번역 + Wiktionary/Wikipedia 교차검증 + 문장 요소 대응을 한 화면에 | 직접 만들고 유지해야 하며, 속도는 일반 번역 앱보다 느림(10장) |

> 정직한 평가: 번역 **정확도** 자체는 B(일반 번역 앱)가 더 낫거나 비슷할 수 있다. E의 가치는
> "세 언어를 한 화면에서 대응시켜 보기"와 "검증 단서 제공"에 있고, 이를 못 살리면 채택 이유가 없다.

## 5. 선택한 API와 모델

| 구분 | 역할 | 키 | 비고 |
|---|---|---|---|
| **NVIDIA NIM** (OpenAI 호환 `chat/completions`) | 번역·언어 감지·품사·예문·문장 대응 | 필요 | 서버(`serve.py`)만 호출. 키는 브라우저로 내려가지 않음 |
| Wiktionary REST | 정의, 모델 번역 대조 | 불필요 | 영어판 기준 |
| Wikipedia REST | 명사 요약·이미지 | 불필요 | 동음이의 문서 제외 |
| MyMemory | 키 없을 때의 **대체** 번역 | 불필요 | v1의 주 엔진이었음 |
| PokeAPI + PokeAPI/sprites | 배틀의 포켓몬 이름(한국어)·**애니메이션 픽셀 스프라이트** | 불필요 | 1~5세대(1~649번)만 — 650번부터는 픽셀 스프라이트가 없음(실측: 649종 전부 앞/뒤 존재). 입력 내용은 보내지 않음 |
| digi-api.com | 배틀의 디지몬 이름·그림 | 불필요 | 일러스트(흰 배경)를 브라우저에서 도트 아트로 변환. 입력 내용은 보내지 않음 |
| jsDelivr (Galmuri 폰트) | 한글 픽셀 폰트 | 불필요 | SIL OFL 1.1. 버전 고정(2.40.3). 실패하면 시스템 글꼴 |
| Web Speech API | 발음 | 내장 | |

**MyMemory를 주 엔진에서 내린 이유 (실측)**
- 한국어↔스페인어 직접 번역 품질이 낮다: `안녕` ko→es → `annyo`.
- 영어를 거치면 다른 문제가 생긴다: `안녕` ko→en → `bye bye`(match 1.0). 뜻이 "hello"가 아니라 "bye"로 굳어 2단계 번역으로 오류가 전파된다.
- 신뢰도 점수가 정확성과 어긋난다: `I love learning new languages`(en→es)에서 가장 높은 점수(0.91)는 **다른 문장**(`I love learning languages`, "new" 누락)의 메모리였고, 정확한 기계번역은 0.85였다.
- 오류도 번역 필드로 내려온다(예: 같은 언어쌍 요청 → `responseStatus 403`, 본문에 오류 문구).

**LLM 모델 선정 (실측: 모델 목록에 있어도 실제로는 쓸 수 없는 모델이 있음)**

| 모델 | 결과 |
|---|---|
| `nvidia/nemotron-3-super-120b-a12b` | **5~10초, 정상 JSON → 기본값** |
| `openai/gpt-oss-20b`, `deepseek-ai/deepseek-v4.1-flash` | 정상이지만 50~76초 → 2·3순위 폴백 |
| `google/gemma-4-31b-it` | 요청은 받지만 60초 넘게 응답 없음 |
| `mistral-large-2`, `llama-3.1-nemotron-70b`, `gemma-3-12b` | 404 (이 계정에서 미제공) |
| `meta/llama-3.3-70b-instruct` | 410 (폐기) |
| `nvidia/riva-translate-4b-instruct-v2` | 빠르지만(0.6초) JSON 형식을 지키지 않아 부적합 |

**검토 후 제외**: dictionaryapi.dev(실측 404, 서비스 중단으로 판단), KRDict 한국어기초사전(키 발급 필요, 추후 후보).

### 6-1. 디자인 컨셉: 픽셀 아트 RPG (v2.1)
**왜**: 사전 찾기와 공부는 지루하고, 번역을 기다리는 10~40초는 특히 길다. 기다리는 시간에도 볼거리가 있게 하고, 기존 배틀 연출(포켓몬·디지몬)과 어울리는 "게임 화면"으로 통일한다.

**원칙**
- 정보 구조는 그대로 둔다. 꾸밈이 읽기 흐름을 해치지 않게, 본문은 밝은 종이색 창 위의 어두운 글씨로 대비를 확보한다.
- 팔레트는 Sweetie-16 하나로 UI·스프라이트·이미지 변환을 통일한다. 언어 색은 EN 하늘색, ES 주황, KO 초록.
- 도트 그림은 이미지 파일 없이 코드(글자 비트맵 → SVG)로 만든다. 저장소가 가볍고, 색과 크기를 코드에서 바꿀 수 있다.
- 외부 그림도 테마에 맞춘다. 포켓몬은 픽셀 스프라이트(왼쪽은 뒷모습), 디지몬과 위키 사진은 브라우저에서 도트 아트로 변환한다(배경 제거·팔레트 양자화·외곽선).
- 움직임은 `steps()`로 끊어 프레임 애니메이션처럼 보이게 하고, `prefers-reduced-motion`이면 전부 끈다.

**재미 요소**: 마스코트 슬라임이 상태를 표정과 말풍선으로 알려 주고 사용 팁을 말한다 / 글자가 한 자씩 찍힌다 / 5개 저장할 때마다 레벨 업 / 저장하면 별가루.

**비용·위험**: 폰트가 외부 CDN 의존이다(실패 시 시스템 글꼴로 대체). 포켓몬·디지몬 이미지는 외부에서 불러오고 저장소에는 넣지 않는다(상표 고지).

## 7. 판단 규칙 ↔ 그리기 분리
- **서버(`server/`) — 검증 계층**
  - 모델 응답을 JSON 스키마로 검증한다(언어 판정, 두 대상 언어 번역 필수, 다른 뜻 최대 3개).
  - 문장 대응은 모델이 준 조각이 **실제 문장의 부분 문자열**이고 중복 사용이 아닐 때만 인정한다(환각 방지).
  - 모델 폴백 체인: 404/410/시간 초과(30초)/형식 오류 시 다음 후보로.
  - Wiktionary 정의와 모델 영어 번역을 대조해 `confirmed`를 계산한다.
  - 호출 제한(IP당 분당 16회), Host 검사, `web/` 안의 `.html/.css/.js` 외 정적 파일 차단.
- **프론트 판단 함수 (DOM 무관)**: MyMemory 응답 해석(상태·한도·빈 결과를 오류로 처리, 입력과 같은 segment 우선), 대체 모드용 언어 감지, 문장 안 조각 위치 찾기.
- **그리기**: 정리된 데이터를 받아 DOM에 꽂기만 한다. 모든 문자열은 `textContent`로만 삽입한다(XSS 방지).
- 사용자 입력은 `<text>` 태그로 감싸 프롬프트에 넣어 "데이터일 뿐 명령이 아님"을 명시한다(프롬프트 인젝션 방어).

## 8. 고정 파일(fixtures) — 폐기
- v1은 `en|es`, `en|ko` 응답 사본으로 API 없이 화면을 재현하려 했다.
- **폐기 이유**: 실제로는 존재하지 않는 경로(`./fixtures/`)를 읽어 항상 실패했고, 파일 내용도 실제 응답(`_NOTE`)을 손으로 고친 값이라 "반드시 실제 JSON으로"라는 이 문서의 원칙을 스스로 어겼다. 입력과 무관하게 같은 결과를 보여주는 문제도 있었다.
- 가짜 샘플 파일은 삭제했다(저장소에도 올린 적 없음). 화면 캡처는 라이브 호출 결과로 대체했고, 필요하면 "서버가 실제 응답을 녹화해 재생하는 방식"으로 다시 만든다.

## 9. 출처 표기
화면 하단에 상시 노출한다.
- 입력이 전송되는 곳: 문장은 선택한 엔진(NVIDIA 또는 MyMemory), 단어 하나는 Wiktionary·Wikipedia.
- "기계번역이므로 참고용", 사전·백과는 Wiktionary·Wikipedia(CC BY-SA)에서 가져옴.
- 배틀 연출은 PokeAPI·digi-api.com에서, 폰트는 jsDelivr(Galmuri, OFL)에서 불러오며 입력 내용은 보내지 않음. 포켓몬·디지몬은 각 권리자의 상표.
- 팔레트 출처: Sweetie-16(GrafxKid, CC0), ENDESGA 32(ENDESGA).

## 10. 완료 후 — 처음 문제가 줄었나?

**측정한 사실 (2026-10-07)**
- 번역 결과(3카드)까지: 약 7~10초. 문장 대응까지 모두 도착하는 데: 약 20~40초.
- 정확성 단서: 단어 조회 시 모델 번역을 Wiktionary와 대조(`casa`→`house` ✓, 틀린 값 `banana` ✗로 검출됨).
- 한 번의 입력으로 세 언어를 동시에 확인할 수 있다 — 이 부분은 의도대로 해결됨.

**아직 측정하지 못한 것 (직접 작성)**
> 전엔 표현 하나당 최소 2개 사이트를 오가며 약 __초 걸렸는데, 이 도구로는 입력 1번에 약 __초 만에 3개 언어를 봤다 → 줄었다 / 줄지 않았다.
> 그동안 잘못된 번역을 걸러낸 횟수: __회 (✓/⚠ 표시가 실제로 도움이 됐는가)

> 주의: 위 측정은 속도가 일반 번역 앱보다 **느릴 수 있다**는 점을 보여 준다. "줄었다"고 쓰려면 기준선(전에 걸리던 시간)을 먼저 재야 한다.

## 11. 알려진 한계
- LLM 번역은 틀릴 수 있고(예: 예문의 언어별 문장이 어긋남), 문장 대응도 AI가 나눈 것이라 어색할 수 있다. 화면에 "참고용"을 표시한다.
- NVIDIA 무료 티어는 느리고 간헐적으로 실패한다. 동시에 여러 명이 쓰면 더 느려진다.
- Wiktionary·Wikipedia는 영어판 기준이다.
- 같은 와이파이 공유(`--lan`) 시 접속자 모두가 내 키의 쿼터를 쓴다. 호출 제한만 있고 인증은 없다. 인터넷 공개용이 아니다.
- 배틀 연출은 본 목적(학습)과 무관한 부가 기능이며, 디지몬 승패는 무작위다.
- 배틀의 포켓몬은 1~5세대(649종)만 나온다(그 이후는 픽셀 스프라이트 없음).
- 디지몬·위키 사진의 도트 변환은 근사치라 복잡한 그림은 뭉개질 수 있다.
- 폰트·배틀 이미지가 외부 의존이라 오프라인이면 폰트는 시스템 글꼴로, 배틀 상대는 "?"로 대체된다.
